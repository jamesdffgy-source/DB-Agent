# DBQuill 项目长期记忆

最后更新：2026-08-31 +08:00

## 1. 产品定义

DBQuill 是一个开源、本地优先的 Windows AI 数据库智能体。用户可以先进行问候、感谢、能力/用法询问等基础沟通，再通过自然语言查看数据库结构、查询和分析数据、检索记录内容，并在受控流程中提出写入操作。

产品核心不是单独的 NL2SQL，而是：

`自然语言 → 结构化数据库操作计划 → 安全策略 → 专用执行器 → 可解释结果`

每个操作计划包含版本、动作、读写模式、意图、目标表、风险、是否需要确认、状态、自研引擎标识、置信度、理由和 SQL（生成后）。

## 2. 不可遗忘的产品决定

- 品牌名和仓库短名保持 `DBQuill`；面向搜索、README 和仓库简介的公开展示名使用
  **DBQuill — Open-Source AI Database Agent**，中文为“DBQuill — 开源 AI 数据库智能体”。
  `open-source` 只描述 MIT 许可下的项目源码，不暗示模型、用户数据或第三方服务开源，也不改变
  Windows 源码优先发布、OpenAI-compatible 模型接口和当前数据库验证边界。
- 完全自研，不接入、不依赖、不复制外部数据库助手框架。
- 公开 benchmark 只用于暴露架构缺口；不以 gold SQL 的 JOIN 顺序、等价 GROUP BY、
  子查询风格或旧解析器偏好决定生产 SQL。任何架构修复都要有问句、schema、显式
  业务证据、关系代数或真实 SQLite 夹具的独立证明。
- NL2SQL 长期方向是将可证明的语义逐步上移到类型化 IR 与本地确定性计划，而不是无界
  增加 Prompt 规则或依赖模型自评。当前 1.10 已表示关系路径、聚合阶段、类型化过滤与排序、
  集合交/差、实体去重计数、负相关、按问句顺序的物理输出、“实体标签 + 关联记录数”混合输出、
  关系数量阈值、标量 arg-min/arg-max、同一父实体多值覆盖、精确引号字面量、限定负关系、
  可见元组集合去重和确定性单行 tie breaker，并以统一 `result_grain` 绑定输出所有者、实体键、
  可见列、基数和重复语义，以 `aggregate_subjects` 区分事实行、去重实体与指标值，以
  `value_domain_requirements` 区分业务数值域和物理存储类型；简单排名候选只缺已证明稳定键时由本地编译器
  追加键，完整可见元组只缺集合语义时增加 `DISTINCT`，唯一抽样枚举可只修正大小写或把未经授权
  的通配收窄为等值。编译器最多 4 步单调组合，禁止 SQL 循环，最后重跑全部门禁且不调用模型重写
  整体关系计划。唯一标量阈值证据优先于关系计数推断，唯一 schema 输出绑定优先于旧投影启发式；不完整时
  必须整句回退或 fail-closed，不执行部分语义。
- 公开 benchmark runner 必须将模型余额、鉴权、限流和服务中断与 SQL 语义失败分开；发现终止型
  依赖错误时只排空已在飞请求并立即停止提交，保留可安全续跑检查点；基础设施失败不进入正确率分母。
- 公开准确率不得只报 Exact 或单发布库执行。完整模型轮必须保存原始预测，并依次报告 Exact、SQL
  有效性、官方解析覆盖、单库执行、严格产品 TSA、上游兼容 TSA 和固定上游逐题交叉校验；重复轮
  还必须区分稳定通过、稳定失败和候选波动。单库通过、多扰动失败是数据偶合假阳性；不同 Prompt、
  模型时间点或生成契约的分数不能作单变量因果比较，any-pass 事后 oracle 不能当生产结果。
- 大 Schema 上下文不能靠固定前 N 列或无差别主键优先。问句链接先使用全库词频、保守单复数归一
  和 token 边界抑制系统化名称噪声；列预算先保留可信命中表之间唯一最短的声明 FK 路径，再保留
  问句相关列和命中表主键。等长多路径必须保持无权威；未展开表用分块索引保留全部表名与省略数。
  静态 Schema 的 token/词频/字典索引应按结构签名预编译并在列名、PK/FK 或字典变化时自动失效；
  重复标识符共享不可变分析，FK 图仅在多表命中时惰性构建，不能用永久对象缓存换取错误上下文。
  合成压力只证明确定性召回、上下文边界和本地冷/热性能，不能冒充真实模型选表准确率。
- 保留我们自己的规划协议、执行器、安全确认、桌面交互、会话和调度体系。
- 基础沟通与数据库执行必须分域：整句高置信社交表达可由本地规则直接回应，不调模型、不读数据、不生成 SQL；含礼貌前缀的真实查询/写入仍进入数据库主链。基础沟通打断待澄清任务时保留原结构化状态，但不把该能力描述为开放域通用助手。
- 源码树只保留 DBQuill 当前主链；任何非本项目通用会话、服务管理、垂直推荐前后端和旧浏览器自动化资产都不得作为“备用能力”继续挂载。若需新增必须重新立项、审核来源和安全边界并追加 ADR。
- 查询默认物理只读；所有写操作必须先预览，再由用户显式确认。
- 通用写入能力询问和缺值 INSERT 的交互意图由模型优先输出结构化
  `write + guided_insert + target_table`；模型建议的表名只能绑定当前授权 schema 中唯一存在的
  真实表，无法验证时退回授权选表。模型不可用或输出非法时，本地安全兜底只能保留录入入口，
  不能猜表、字段和值。SQLite 与显式启用受控读写的 MySQL/PostgreSQL 结构化单行录入显示真实字段和一行经只读安全层获取的
  原表示例；表单值本地类型化并编译为单条 INSERT，完整复用写校验、回滚预览、一次性确认单、
  角色门禁、审计与执行前复检。远程查询始终使用独立只读连接；远程写入只开放显式启用的
  INSERT/UPDATE/DELETE，UPDATE/DELETE 强制 WHERE，DDL、BLOB、远程细粒度凭据和行级授权写入不开放。
- 自定义建表不是自由 SQL 编辑器。界面只收集表名、字段名、受控类型和约束；后端
  必须重新校验并确定性编译单条 CREATE TABLE，然后完整经过写校验、DDL 事务回滚
  预览、一次性确认单、admin 批准、脱敏审计和执行前复检。任何库/表/字段/行范围
  受限凭据和未验证的远程方言都不允许通过该入口执行 DDL。
- 自动图表只分析基础业务表，FTS 虚拟索引和 `_data/_idx/_docsize/_config/_content`
  影子存储不是业务事实，不得生成图表或进入缓存。同一快照的 schema/采样/聚合应复用一个
  范围化只读连接；图表必须提供可见行数、分组/覆盖/截断语义和确定性摘要，不把装饰性图形冒充业务分析。
- 会话里的模型上下文与桌面历史展示不是同一数据合同。模型只接收有界文本预览，避免上下文和
  数据暴露随结果规模增长；桌面可为只读回答另存有界富快照（最多与查询物化硬上限一致的 500 行，
  并保存真实总行数），以便切换会话后恢复表格。表格默认显示 10 行，超过时可展开全部当前已返回/
  已保存行；载荷边界导致未完整保存时必须明确区分已保存数和真实总数。富快照不得包含写确认单、确认 ID 或可操作写表单，
  只能由通过原数据库/访问范围校验的会话详情接口返回，删除会话时一并删除。
- 工作检查点只使用当前会话最近最多 14 条有界消息，不属于长期记忆。完成的读取事件先以 `pending` 状态分期，回答不等待第二次模型请求；
  异步 `MemoryReflector` 只读脱敏问题预览、真实执行成败、表/动作和数量元数据，提议舍弃、L4、L2、L3 或 L2+L3。模型输出不是写入授权：L0 代码内不可写，L1 只由程序生成；L2 需成功且未纠错的执行及最低置信度，L3 还需更高置信度和可复用性。失败/已纠错事件最多保留 L4，低分建议由本地门禁降级；舍弃事件不索引且清除问题预览/词元。
  所有对象绑定稳定数据库引用、授权范围和 schema 指纹，不保存 SQL、结果行、连接信息、凭据或模型提示。首次及每次纠错后均需三次有效成功证据才晋级。删除会话要回收对应及其派生支持；用户可停用策略、清空当前范围或对失败反思发起重试。模型建议、有效层和本地门禁原因必须可查；记忆仍只能影响只读路由，不能控制写入、权限或安全门禁。
- 定时自动化只允许物理只读查询；定时自然语言若规划为写操作必须停在确认边界，不能自动批准。旧版定时写任务必须停用，不能以兼容性为由保留旁路。
- 本地 API 必须执行 viewer/operator/admin 三角色最小权限，不能只靠前端隐藏按钮。DELETE、DDL、未知或超过 100 行的写提案必须管理员批准；操作员只可批准已预览的有界 INSERT/UPDATE。越权不得消费确认单。
- 需要区分本地使用主体时，发行有强制有效期、可单独吊销且仅存 token 哈希的个人凭据；原始 token 只显示一次。凭据名称是本地管理员标签，不得描述为经过核验的个人账号、MFA 或企业 IAM。
- 新发行个人凭据必须明确选择全部数据库或一个非空数据库引用集合；数据库范围由服务端覆盖列表、请求体及 session/run/schedule 间接 ID，不能只靠前端筛选。本地 SQLite 可进一步限定每库表集合，必须同时过滤 Schema/语义/图表/会话并由 SQLite authorizer 约束真实查询、RAG、预览和写事务；没有等价执行门禁的远程表范围不得开放。受限 admin 不得管理全局凭据或全局审计备份；共享角色 token 与 v1/v2 迁移凭据保留原有全库/全表兼容，必须如实标记。
- UI 走克制、清晰、低装饰路线；解决重叠问题，顶部常用操作同时显示图标和文字。
- 左上角品牌旁提供克制的中文/English 切换。界面语言优先读取本机已保存选择，首次使用按系统语言选择；
  翻译目录和动态 DOM 翻译完全在本机运行，不调用模型或外部翻译服务。切换只影响应用控件、提示和
  数字格式，不翻译数据库名、表名、用户问题、查询结果或历史业务内容，也不改变模型配置与执行语义。
- 本地优先、低依赖和可审计安全链路是核心差异，不追求堆叠概念或功能数量。
- 源码发布必须可从干净 Windows/Python 3.12 克隆复现：直接依赖和完整闭包分别精确锁定，安装校验
  下载哈希；运行时选择不得只硬编码本机便携 Python。许可证、第三方署名、Git 候选文件秘密扫描、
  CI 契约和受控发布资产必须进入完成门禁。无法证明再分发许可的二进制不得留在发布树。
  源码指纹必须跨 Git LF/CRLF checkout 稳定；文本按规范化 LF 计算，ZIP/字体/图片按原字节计算。
- 审计只保存受控脱敏元数据；写执行与语义变更必须先通过审计可用性和完整性门禁。哈希链用于发现普通修改和断链，不得描述为外部签名、WORM 或能抵御本机完全写权限攻击者。
- 审计历史前缀可以导出为只含 count/head hash 的锚点并在账本增长后复验；只有把文件保存到独立受保护位置才增加外部证据价值，不能把未移出的 JSON 描述为外部锚定、签名或 WORM。

LLM 通过项目专用 `model_gateway.generate_text` 访问 `model_profiles.json` 配置的 OpenAI 兼容接口。网关只负责 prompt 到文本的传输、重试、截止时间、取消和用量计数，不提供通用工具循环或自治会话。基础沟通和结构查看不需要 LLM；不完整写入的交互意图优先由模型结构化识别，但表单 schema、示例读取、值校验、SQL 构造、预览和确认均为本地受控流程，模型不可用时只允许安全兜底到选表入口。复杂查询、检索组织、组合分析和其他自由写 SQL 生成目前会使用 LLM。

`desktop_bridge.py` 同时把自然语言终态、写确认/执行、语义变更、调度配置和调度运行写入独立 `db_audit_store.py`。账本为本地 SQLite 追加式事件链，只接收白名单元数据及问题/SQL/目标/确认单指纹；账本可对批准/待处理与终态进行未决对账，并创建绑定事件链、head hash 与文件 SHA-256 的本地备份。离线脚本还支持可独立验证的单文件外部备份、外部前缀归档/锚点、本地与外部备份隔离恢复演练，以及带安全备份和 current-head 防竞态的真实恢复。桌面“审计记录”工作台通过受鉴权 API 查询、校验、脱敏导出和创建本地备份；任意外部路径和恢复操作只允许离线脚本执行。

`db_access_control.py` 在既有主 token 上定义 `local-rbac-v1`：主 token 是 admin，viewer/operator token 用带版本域的 HMAC-SHA256 单向派生。`db_identity_store.py` 另提供可选的独立本地凭据，只保存 token 哈希及名称/角色/生命周期，并以 schema v5 保存 `all/restricted` 数据库范围、稳定 SHA-256 数据库引用、每库可选表、每表可选字段集合和结构化行条件。`desktop_bridge.py` 在 token、同源和角色校验后执行数据库/表/字段/行范围门禁，覆盖直接 `dbId` 与 run/session/schedule/confirm 间接绑定；`DBQuillAgent` 对数据受限 SQLite 只构建授权 Schema，并在 SQL、RAG、图表、预览和最终写事务安装 authorizer，行范围以 TEMP 过滤视图承载且完全只读。请求上下文把角色及 `credential_ref` 传给异步自然语言审计；权限拒绝只记录角色、凭据短引用、范围数量和路由指纹，不记录表/字段/行值。共享角色 token 仍兼容，本地名称不是外部身份认证。

## 4. 已实现能力

### NL-to-Database

- 统一 `DatabaseOperationPlan` 数据协议。
- `IntentResult` 除四类数据库意图外记录 `interaction/target_table/source`；不完整录入由模型识别为
  `guided_insert`，目标表经授权 schema 二次校验后才可直接打开对应录入表单。
- 自然语言动作映射：查看库结构、查看表结构、读取、检索、组合分析、新增、更新、删除、创建结构、修改结构、删除结构。
- 表名目标识别、读写模式、风险等级、确认需求和状态跟踪。
- “有哪些表、每张表多少行、某表有哪些字段”等结构问题直接读取元数据，不调用模型。
- 查询和写入回答都携带操作计划，前端显示动作、模式、目标、风险和状态。
- 操作计划引擎标识为 `native`，明确为本项目自研链路。
- 自研歧义门禁：模糊写入、缺少筛选条件、未定义字段的建表/改表，以及多表下的泛化单表查询会暂停执行并请求补充。
- 澄清支持结构化连续对话；待补充上下文同时保存在内存和会话 SQLite，bridge 重启后可以继续。
- 前端提供“需要补充”卡片、候选表/字段快捷按钮，并在无候选项时聚焦输入框。
- 组合分析先生成自研 `OperationGraph 3.1`：量化表达选择查询，内容/原因类表达选择检索；明确“分别/各自”的 2–6 表请求按目标表拆为受范围约束的独立查询；支持固定 `has_data` 条件。

### 查询与安全

- SQLite 查询使用只读 URI 和 `PRAGMA query_only=ON`。
- 只允许单条 SELECT/WITH 查询；拦截写入关键词和危险形式。
- 自动限制返回行数，并使用有界读取避免大结果全部物化。
- 写操作支持 INSERT/UPDATE/DELETE/CREATE/ALTER/DROP 的校验和事务预览。
- UPDATE/DELETE 必须带 WHERE；写入不直接执行。
- 一次性确认单绑定数据库路径，避免跨库确认；执行前再次校验，失败回滚。
- 删除记录与删除表在自然语言计划层分开识别，高风险操作明确标记。
- 明确的字段增加、删除、修改或重命名不会再被结构查看规则抢先识别，必须进入写操作的歧义校验、预览和确认链路。
- 写确认在调用执行器前必须先登记批准/拒绝事件并验证审计链；账本不可用或链异常时拒绝执行。自然语言只读审计失败不改变原查询结果。执行后结果事件与用户数据库属于两个事务域，当前不能承诺跨库原子提交。

- 查询结果有界读取。

## 8. 运行注意事项

- 支持的 Python 为 CPython 3.12；CI 与 `.python-version` 选择可用的 3.12 补丁版本，正式门禁另行
  记录实际解释器。现有工作区可用 `runtime/python/python.exe`，干净源码克隆通过
  `scripts/bootstrap_dev.cmd` 创建 `.venv`，也可用
  `DBQUILL_PYTHON` 显式选择解释器。3.12.10 干净导出安装已通过，不外推到其他主/次版本。
- 业务查询使用 `runtime/app/frontends/timezone_releases/` 中的项目归档，不依赖主机 `TZPATH`；便携 Python 的 `tzdata 2026.3` 只保留为当前发行和人工候选构建来源。
- 测试和启动统一使用 `scripts/run_python.cmd`；不要绕过锁文件假设任意系统 Python 已安装依赖。
- Python 后端是常驻进程，修改核心代码后必须重启桌面应用才能生效。
- Python 后端和前端资源没有热加载；完成代码更新后，应完整重启 DBQuill 以加载最新 NL-to-Database 能力。
